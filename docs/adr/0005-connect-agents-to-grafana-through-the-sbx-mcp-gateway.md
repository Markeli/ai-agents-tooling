# 0005. Подключать агентов к Grafana через mcp-grafana на хосте и шлюз MCP sbx

- Status: Accepted
- Date: 2026-11-28
- Related: [спека](../specs/2026-11-28-grafana-mcp.md)

## Context

Агентам — боту `markeli-agent` в песочнице sbx и Claude Code / Claude Desktop владельца на Mac — нужен доступ к
метрикам (VictoriaMetrics), логам (VictoriaLogs), дашбордам и алертингу машин владельца. Всё это есть в Grafana
(`https://grafana.markelow.me`, `iaac/doco-cd`). Официальный MCP-сервер Grafana,
[mcp-grafana](https://github.com/grafana/mcp-grafana), с v2.4.0 умеет и метрики (Prometheus-инструменты), и
VictoriaLogs (Loki-инструменты, LogsQL); работает локально по stdio или сервером по HTTP.

sbx дает агентам в песочнице один MCP-эндпоинт — шлюз на хосте: серверы регистрируются на хосте (`sbx mcp add`),
локальные stdio-серверы запускаются на хосте, секреты остаются на хосте. Документация sbx о серверах внутри VM молчит
и предлагает считать локальные серверы доверенными интеграциями хоста. Секреты `mcp:*` в песочницы не попадают.

У шлюза два режима: динамический (по умолчанию; агент сам находит и подключает любой зарегистрированный на хосте
сервер через `mcp-find`/`mcp-add`) и статический (`--static-mcp`; песочница получает только перечисленные серверы).

Любой токен Grafana дает чтение всех метрик и логов; в логах есть текст из интернета.

## Decision drivers

- Токены не попадают в VM песочницы; на Mac — только в Keychain.
- Никаких новых публичных сервисов.
- Один способ для песочницы и для Claude Code / Desktop владельца.
- Как можно меньше своего кода и релизов образа.
- Раздельный отзыв доступа бота и владельца.

## Considered options

### Вариант 1: mcp-grafana на Mac, в песочницу — через шлюз sbx

Одна установка (`brew`), запуск с токеном из Keychain; sbx регистрирует его как локальный stdio-сервер, Claude Code и
Desktop — как свой.

- Good: родной механизм sbx; токены на хосте; ни образа, ни кита, ни `agent-sandbox` менять не надо; обновление —
  `brew upgrade` для всех клиентов; два service account отзываются по отдельности.
- Bad: mcp-grafana работает на хосте вне изоляции песочницы: ошибка в нем, вызванная запросом агента, затронет Mac, а
  не VM (сервер только читает и пишет в API Grafana; риск небольшой). Настройка на хосте — по инструкции, не
  автоматически.

### Вариант 2: mcp-grafana в образе песочницы

Бинарник в образе, плагин Claude Code с `.mcp.json`, credential кита подставляет токен.

- Good: сервер изолирован в VM.
- Bad: свой механизм в обход шлюза (секреты шлюза в VM не попадают, нужен credential кита); релиз образа на каждое
  обновление; Mac владельца — отдельная установка.

### Вариант 3: общий сервер mcp-grafana на geonosis (HTTP за nginx)

- Good: одно место настройки.
- Bad: новый публичный сервис в сети стека `monitoring`, где VictoriaMetrics и VictoriaLogs доступны без авторизации;
  один общий токен доступа к MCP; больше всего работы.

### Вариант 4: без MCP — curl к API Grafana или CLI `gcx`

- Bad: у `gcx` нет VictoriaLogs; сырые запросы `/api/ds/query` агент собирает с ошибками.

### Режим шлюза: динамический или статический

Статический закрывает песочнице доступ к серверам хоста, которых ей не дали, но требует подключать серверы с хоста
(флаг в `agent-sandbox`, `sbx mcp load`). Пока на хосте зарегистрирован только `personal-grafana`, разницы нет.

## Decision

Chosen option: **вариант 1, динамический режим шлюза**, потому что это штатный путь sbx, токены остаются на хосте,
одна установка обслуживает и песочницу, и Claude Code / Desktop, а своего кода почти нет. Статический режим
откладываем до появления на хосте других MCP-серверов (например, рабочих).

## Consequences

- Positive: бот и владелец работают с Grafana без изменений образа и `agent-sandbox`; после пересоздания песочницы
  агент сам подключает `personal-grafana`.
- Negative: любой агент в любой песочнице может подключить любой зарегистрированный на хосте сервер; mcp-grafana
  работает вне изоляции; права ограничены ролью Editor и списком инструментов, а не песочницей.
- Follow-ups: при регистрации на хосте других MCP-серверов — статический режим и опция `--mcp` в `agent-sandbox`
  (новый ADR).
