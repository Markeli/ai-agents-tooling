# watch-pr Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** the `watch-pr` skill and script that wake the bot on review and CI events of its PRs/MRs, shipped in the
sandbox image built from `skills/claude-code` too.

**Architecture:** one bash script, `watch-pr`, split by responsibility. A host adapter (`github.sh`, `gitlab.sh`)
turns one poll into a normalized JSON snapshot. The core (`watch-pr`) diffs the snapshot against the per-session
state, prints event lines, and runs the loop, the lock, the limits and the exit codes. Claude Code runs the script as a
`Monitor`; `SKILL.md` and `source-control.md` tell the bot how to start it and what to do with its lines.

**Tech Stack:** bash, `jq`, `gh api graphql`, `glab api`, `flock`; tests in plain bash with stub `gh`/`glab`
(the style of `.github/scripts/tests/run.sh`); Docker named build contexts.

**Spec:** [`docs/specs/2026-11-14-watch-pr.md`](../specs/2026-11-14-watch-pr.md),
[ADR 0004](../adr/0004-build-the-sandbox-image-from-the-repository-skills-too.md)

## Global Constraints

- Poll interval 30 s (`--interval`), `--max-runtime` 1500 s then exit 3; Monitor `timeout_ms` 1800000.
- Exit codes: 0 merged/closed (and `--once`), 1 fatal API error, 2 usage/environment, 3 max runtime.
- Event line: `watch-pr <ref> <kind> <author> <url> <excerpt>`; `<ref>` `owner/repo#N` or `group/project!N`;
  excerpt = first 200 characters of the body on one line, session marker stripped; `-` for an empty field.
- Kinds: `comment | thread | reply | review | ci-failed | merged | closed | warning | error`.
- Allow-list `/etc/claude-code/watch-pr/authors`, `<host> <login>` per line, `#` comments, case-insensitive;
  ships `github.com Markeli` and `gitlab.com markeli` only; `--authors` overrides.
- Session marker `<!-- watch-pr session=<id> -->`, last line of every body the bot posts. A `markeli-agent` item is an
  event only with another session's marker.
- State `${XDG_STATE_HOME:-$HOME/.local/state}/watch-pr/<session>/<host>/<project>/<number>.json`; `<session>` from
  `--session`, else `$CLAUDE_CODE_SESSION_ID`, else exit 2. Deleted on merged/closed; session dirs untouched 30 days
  deleted at start.
- Warning after 10 consecutive failed polls, once until a poll succeeds; 401/403/404 on the PR/MR → `error`, exit 1.
- GitHub: one GraphQL query per poll; below 20% of `rateLimit.limit` remaining, poll every 300 s until `resetAt`.
- Only `bash`, `gh`, `glab`, `jq`, `flock` (util-linux, in the image). Lines ≤ 120 characters; shellcheck clean with
  `LC_ALL=C.UTF-8`.

## Review Focus

- A comment body with newlines, tabs, quotes or `$(…)` → printed as one line, never evaluated (Task 3 test
  `body_is_one_safe_line`).
- A GitHub rate-limit 403 ("API rate limit exceeded", "secondary rate limit") → transient, not fatal (Task 5 test
  `rate_limit_403_is_transient`).
- The owner replies twice within one poll interval → two `reply` lines in creation order (Task 3 test
  `two_replies_in_one_poll`).
- A PR whose head commit changes between polls with the old failed check still listed → the new commit's failure is
  reported, the old one is not repeated (Task 3 test `ci_failed_once_per_head`).
- `/watch-pr` run outside a git repository without a URL → exit 2 with a clear message, no polling (Task 2 test
  `no_repo_no_url`).

### Task 3: GitHub snapshot and event diffing

**Files:**
- Create: `skills/claude-code/watch-pr/github.sh` (sourced by `watch-pr`)
- Modify: `skills/claude-code/watch-pr/watch-pr` (core diff and output)
- Create: `skills/claude-code/watch-pr/tests/fixtures/github-*.json` (GraphQL responses)

**Interfaces:**
- Produces: `github_snapshot` → prints the normalized snapshot on stdout, returns 0, or returns 1 (transient) / 2
  (fatal) with the reason on stderr. Normalized snapshot (shared with Task 6):
  ```json
  {"state": "open|merged|closed",
   "head": {"sha": "…", "date": "ISO"},
   "items": [{"id": "…", "kind": "comment|thread|reply|review", "author": "login", "url": "…",
              "body": "…", "created": "ISO", "verdict": "changes_requested|approved|commented|null"}],
   "failed": [{"key": "<name>@<sha>|pipeline:<id>", "name": "…", "url": "…"}],
   "rate": {"remaining": 0, "limit": 0, "reset": "ISO"} }
  ```
- Produces in `watch-pr`: `diff_and_report <snapshot-file>` — prints event lines for unseen items/failures that pass
  the filters, updates the state file atomically (`mktemp` + `mv`), prints `merged`/`closed` and returns 10 when the
  PR/MR ended.
- GraphQL query (one request): `repository.pullRequest(number)` with `state`, `comments(last:100)`
  (`databaseId author{login} url body createdAt`), `reviewThreads(last:100){nodes{comments(last:100){…}}}` (first
  comment of a thread → `thread`, the rest → `reply`), `reviews(last:100){nodes{databaseId state body url author
  createdAt}}`, `commits(last:1){nodes{commit{oid committedDate statusCheckRollup{contexts(first:100){nodes{
  …on CheckRun{name conclusion detailsUrl} …on StatusContext{context state targetUrl}}}}}}}`, and
  `rateLimit{limit remaining resetAt}`. No paging: `last:100` always holds the newest items, and fewer than 100 new
  ones arrive between two polls, so nothing new is missed (the spec's paging edge case); only a catch-up over more
  than 100 waiting items of one kind would drop the oldest.
  Failing: CheckRun `FAILURE|TIMED_OUT|STARTUP_FAILURE`, StatusContext `FAILURE|ERROR`.
- Filters: item author in `authors`; `markeli-agent` only with another session's marker; `review` only
  `CHANGES_REQUESTED`, or `APPROVED`/`COMMENTED` with a non-empty body; nothing for edits (IDs only).
